# Sprints

A sprint is a shippable slice — a chunk of work the team could plausibly
finish and demo, hand off, or close out as a unit. Sprints are about scope,
not time.

There is no required number of sprints. Some projects break into 3 natural
phases, others into 7. Pick whatever genuinely fits the project — not a
target.

## How to slice

Look for natural seams: the points where the work changes character or
hands off to a different audience. Those are where one sprint ends and the
next begins.

Examples:

- A SaaS launch might split into: Discovery & Design → Backend Foundation
  → Core Features → Billing & Settings → Polish & Launch
- A podcast launch might split into: Concept & Branding → First Three
  Episodes → Distribution Setup → Launch Week → Post-launch Iteration
- A research study might split into: Literature Review → Study Design →
  Data Collection → Analysis → Write-up & Publication

## Naming

Each sprint's name describes WHAT is being shipped, not WHEN. Forbidden:
"Week 1", "Sprint 3", "Iteration 2", "Phase 1" — these names tell the team
nothing. Required: a short noun phrase tied to the deliverable.

A sprint name is good when, on its own, it tells you what's in it.

## What goes in a sprint

The full set of work needed to ship that slice — setup, the core work, the
edge cases, the validation, the handoff. Stop adding tasks when the
sprint's goal is genuinely shippable; don't stop just because you've
written "enough" of them. A sprint with three tasks is fine if three tasks
honestly cover the slice. A sprint with twelve is fine if it actually
needs them.

Avoid filler. Don't pad with vague "set up tooling" tasks just to round
out a count. Every task should earn its place.

## Tasks per sprint

A sprint with 2 tasks usually means the tasks are too broad — check
whether each task is actually one deliverable or several bundled together.
A sprint with 10-12 tasks is normal for a busy sprint. There is no upper
limit if the work genuinely belongs together.

If you find yourself writing a sprint with only 1-3 tasks and the sprint
name implies a large area of work (e.g. "Chrome Extension Core",
"Authentication", "Design"), that is a signal to go back and split the
tasks within that sprint — not to add a second sprint.
