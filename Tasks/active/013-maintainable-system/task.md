# Make AlianHub easy to maintain — for admins, teams and developers

## Context
The redesign (stages 1–5) and the AR-53 sweep left the product working, but the *system* is still hard to keep running and hard to keep tidy: the installer is half-deleted, Docker images cannot create a first company, there is no backup/upgrade/runbook story, first-run seeds a Member with zero permissions, everyday actions hide under "More" menus, and the codebase carries a whole legacy dashboard beside the redesign. The owner wants one overhaul branch that makes a non-developer able to install, configure, upgrade and troubleshoot an instance from the UI plus one guide; makes day-to-day use discoverable and tidy; and leaves a codebase a new engineer can change safely, with legacy paths removed.

## Shape of the work
One overhaul branch `feat/maintainable-system` off `beta`, three workstreams run **in parallel by separate agents in isolated worktrees**, each landing as a series of commits onto the overhaul branch; the branch stays runnable at every merge (`npm test && npm run lint && cd frontend && npm run build`). Tracked as `Tasks/active/013-maintainable-system/` (task.md = this plan, progress.md per workstream; retire the duplicate id 005 by folding first-run into this task).
